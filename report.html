1. Executive Summary & Abstract

In fulfillment of TH Assessment 1 for CSI3029 Front End Design and Testing under the mentorship of Dr. V. Arulkumar (18875), this project presents the end-to-end design, implementation, and automated testing of AyurVeda Naturals (https://ayurvedanaturals.in). Operating as a Digital Solutions Consultant, the primary objective was to modernize a traditional physical Ayurvedic apothecary by engineering a high-performance, aesthetically elevated, and mobile-first e-commerce web platform.

The digital solution addresses the operational limitations of brick-and-mortar herbal dispensaries by introducing: (1) a multi-page semantic architecture built with HTML5, CSS3, JavaScript ES6+, and Bootstrap 5; (2) omnichannel social commerce pipelines integrating direct Instagram deep-linking (@ayur.veda.wellness), WhatsApp Business 1-click cart order string generation (+91 98765 43210), and instant click-to-call telephony; (3) a dual-stage order verification and email confirmation workflow with live HTML invoice rendering and client-side dispatch; and (4) an automated, in-browser test suite verifying cart calculations, Vedic coupon algorithms, and form validations.

2. Business Context & Problem Formulation

2.1 The Traditional Herbal Apothecary Scenario

The client is a physical Ayurvedic wellness store retailing classical herbal Rasayanas (e.g., Pure Himalayan Shilajit, KSM-66 Ashwagandha, Ashtanga Kumkumadi Tailam, and Swarna Chyawanprash Supreme). While possessing authentic botanical knowledge and AYUSH GMP licensing, the physical store suffered from severe commercial constraints:

  • Catalogue Invisibility: Prospective wellness buyers could not inspect botanical ingredients, Sanskrit medicinal texts (Charaka Samhita), or laboratory heavy-metal test certifications remotely.
  • Order Inefficiency: Customers inquiring via WhatsApp or Instagram had to manually type item names, quantities, and prices, leading to human error and abandoned sales.
  • Lack of Customer Order Proof: Traditional telephone orders lacked digital confirmation receipts, causing order delivery discrepancies and anxiety over delivery timelines.
  • Fragmented Order Fulfillment: Storekeepers lacked a centralized digital dashboard to verify prescriptions, accept orders, and trigger official dispatched status.

2.2 Role of the Digital Solutions Consultant

As a Digital Solutions Consultant, our role was to formulate a holistic digital transformation strategy rather than merely building static web pages. We mapped consumer buying psychology in the alternative medicine domain—where trust, botanical authenticity, and seamless communication are paramount—into a friction-free multi-page front-end experience.

4. System Architecture & Data Flow

The architecture utilizes a modular Model-View-Controller (MVC) pattern implemented natively in client-side JavaScript. The data layer (products-data.js) acts as the immutable single source of truth for botanical items, while the state engine (app.js) manages reactive cart state, wishlist state, and order lifecycle transitions inside localStorage.

Architectural Data Flow Pipeline:
AYUR_PRODUCTS (Data) → Products Controller (Filter/Sort/Search) → Reactive DOM (View) → Cart State Manager (LocalStorage) → Checkout Form Validator → OrderService.createOrder() → Automated HTML Email Generator + WhatsApp API Dispatcher → Admin Dashboard State Update.

6.2 Core JavaScript State Management Snippet

// Cart State Engine in js/app.js
const CartState = {
  getCart() {
    try { return JSON.parse(localStorage.getItem('ayur_cart')) || []; }
    catch(e) { return []; }
  },
  saveCart(cart) {
    localStorage.setItem('ayur_cart', JSON.stringify(cart));
    this.updateCounters();
  },
  getTotals() {
    const cart = this.getCart();
    const subtotal = cart.reduce((sum, item) => sum + (item.price * item.quantity), 0);
    const shipping = (subtotal >= SHOP_CONFIG.freeShippingThreshold || subtotal === 0) ? 0 : SHOP_CONFIG.shippingFee;
    const tax = Math.round(subtotal * SHOP_CONFIG.taxRate); // 5% GST
    
    const coupon = this.getAppliedCoupon();
    let discount = 0;
    if (coupon) {
      if (coupon.type === 'percent') discount = Math.round((subtotal * coupon.value) / 100);
      else if (coupon.type === 'flat') discount = Math.min(coupon.value, subtotal);
    }
    const grandTotal = Math.max(0, subtotal + shipping + tax - discount);
    return { subtotal, shipping, tax, discount, grandTotal, coupon, itemCount: cart.length };
  }
};

7. Social Commerce Architecture

7.1 WhatsApp 1-Click Order Link Generation

A key innovation developed for the client is the WhatsApp URI Serialization Engine. Because many Indian customers prefer finalizing orders via messaging, our system transforms the entire active shopping basket into a clean, formatted WhatsApp chat message: 

// Social Commerce WhatsApp URI Encoder in js/app.js
getCartWhatsAppUrl(customerData = null) {
  const cart = CartState.getCart();
  const totals = CartState.getTotals();
  let text = `Namaste ${SHOP_CONFIG.shopName}! 🍃\n\nI want to place an order for:\n\n`;

  cart.forEach((item, index) => {
    text += `${index + 1}. *${item.name}* (${item.netWeight})\n   Qty: ${item.quantity} × ₹${item.price} = ₹${item.quantity * item.price}\n`;
  });

  text += `\nSubtotal: ₹${totals.subtotal}\nGST (5%): ₹${totals.tax}\nShipping: ${totals.shipping === 0 ? 'FREE' : '₹' + totals.shipping}\n*TOTAL PAYABLE: ₹${totals.grandTotal}*\n`;
  return `https://wa.me/${SHOP_CONFIG.whatsappNumber}?text=${encodeURIComponent(text)}`;
}

8. Email Order Confirmation & Store Admin Verification

To satisfy the client's explicit business requirement—"if the order confirms it should go to email confirmation ordered"—we implemented an end-to-end Dual-Stage Email Lifecycle:

Stage 1: Order Placement & Instant Customer Receipt Dispatch

When the customer submits the checkout form, OrderService.createOrder() creates a unique order reference (AVN-2026-XXXX) and generates an authentic HTML email invoice containing itemized line items, GST breakdown, shipping destination, and clinical guidelines. This email is dispatched directly to the customer's mailbox (and simulated inside the interactive Email Modal Viewer) while simultaneously alerting the apothecary manager (orders@ayurvedanaturals.in).

Stage 2: Store Owner Review & Vaidya Approval in Admin Portal

The storekeeper accesses admin-orders.html to review pending formulations and medical notes. Upon clicking "Approve Order", the status updates to Approved, triggering the secondary confirmation email notifying the customer that their prescription has been verified and packed for express dispatch.

12. Challenges, Solutions & Conclusion

12.1 Key Technical Challenges & Solutions

  • Challenge 1: Formatting Multi-line Cart Data for WhatsApp URL: Formatting carriage returns and currency symbols in WhatsApp URLs caused decoding issues on iOS devices. Solution: Implemented native JavaScript encodeURIComponent() on normalized string buffers.
  • Challenge 2: Dual-Stage Order Lifecycle without Server Dependency: A purely static site cannot persist orders across browser refreshes or simulate shopkeeper approvals. Solution: Engineered an asynchronous state machine within localStorage paired with an administrative verification portal (admin-orders.html).
